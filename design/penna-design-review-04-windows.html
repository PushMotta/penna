Penna on Windows

What a Windows version would be: what carries over from Linux, how Windows reaches each kind of fan, how the service keeps the promise that every fan goes back, and six calls before any code.

Linux Penna 0.10.0, 222 Rust tests, 33 plugin tests Carries over penna-core and penna-proto, about 8,000 lines Test bed win-ci, the VM that holds the RTX 2060 SUPER Research 23 October 2026, sources linked

What carries over

The control loop, setup, generated curves, profiles, configuration and the protocol are plain Rust with no operating system in them: penna-core and penna-proto, and most of the tests. The NVML backend builds on Windows as it is. So does the plugin's logic, Model.js, with its tests.

What has to be new

Everything that meets the OS. hwmon gives way to each vendor's own interface, systemd to the Service Control Manager, the Unix socket to a named pipe, and the penna group to a Windows group. The UI needs a new home too: Quickshell runs only on Linux, under Wayland.

What Windows already has

Fan Control, the app Penna took its card model from: free, closed source, released almost weekly, built on LibreHardwareMonitor. A Windows Penna would add what it doesn't have: open source, a setup run that measures every fan and proposes curves, and fans that go back even when the service dies.

A · Shape

One daemon, two operating systems

The same loop and protocol on both. On Windows, pennad is a service running as LocalSystem, the surfaces reach it over a named pipe, and the way back is held in a file before any fan changes, as on Linux.

the same code as on Linux new for Windows later, if call 2 says so the way back
B · Hardware

How Windows reaches each kind of fan

On Linux the kernel's drivers do the chip work, and Penna only writes their files. On Windows, GPUs and laptops have vendor interfaces that play that part. Motherboard fans have none: every tool that drives them brings its own kernel driver and does the chip work itself.

PawnIO · blocklist

LibreHardwareMonitor (MPL-2.0) saves each chip's registers before its first write and restores them when a fan goes back to default or the library closes. A crash restores nothing, because the originals live only in its own process.

C · Safety

Every fan goes back, on Windows too

§6 carries over almost whole. One piece has no Windows equivalent: a watchdog outside the process that kills a hung loop.

On LinuxOn Windows
Type=notify service, as rootA Windows service as LocalSystem, with the windows-service crate.
Restart=on-failure, RestartSec=1The Service Control Manager's recovery: restart after 1 s.
ExecStopPost=penna restoreThe SCM's failure action, which runs penna restore. It fires on a crash, and on a stop with an error once the non-crash flag is set. A clean stop restores by itself, as on Linux.
WatchdogSec=5, then SIGKILLA watchdog thread inside pennad: a loop silent for 5 s means restore from held.json, then exit with an error so the SCM restarts it. A hang that stops the whole process is not covered.
held.json in /run/pennaC:\ProgramData\Penna\held.json, readable only by SYSTEM and Administrators. Changes that outlive a reboot, like the power mode, go to firmware.json beside it, as now.
Unix socket, peer credentials, the penna groupA named pipe, \\.\pipe\penna, created first and refusing remote clients. Anyone signed in may watch; members of a local Penna group may change fans. The client's token says who. Tokio has no Unix sockets on Windows, but it has named pipes.
systemd stops the unit at shutdownThe pre-shutdown notice, 10 s by default: every fan back, then stop.
Removing the package stops pennadThe uninstaller stops the service, which hands every fan back, then runs penna reset.
D · The app

A home for the popup and the studio

The plugin's 14 components, about 2,400 lines, import only QtQuick, the shell's theme tokens and a few of its controls. The popup, studio and service windows, about 1,700 lines, belong to the shell. Model.js and its 33 tests carry over to any of these three.

Recommended · call 4

A Qt Quick app

  • The components run as they are, with a small module that gives them the theme tokens and controls the shell gave them.
  • New windows for the popup and the studio, and the glyph in the tray.
  • Qt's local socket speaks named pipes on Windows and Unix sockets on Linux.
  • The same app serves Linux desktops outside Omarchy, which §10 lists for v2.
  • Cost: a small C++ host, and Qt's runtime shipped with it. MPT already ships Qt on Windows.
Alternative

Tauri, on WebView2

  • A Rust host and the system's web view: a small download.
  • Model.js runs as it is.
  • Every component drawn again in HTML and canvas, and the motion rules of §8.6 rebuilt.
Alternative

egui on wgpu

  • Pure Rust, one binary, the option §10 names for v2.
  • Everything drawn again, Model.js included.
  • Immediate mode makes the glide and text easing of §8.6 hard to match.
E · Shipping

Signing, installing, testing

Signing

SmartScreen warns about unsigned downloads, and since 2024 no certificate skips that: reputation builds over time. Microsoft's Artifact Signing, about $9.99 a month, is open to individuals only in the US and Canada, so it isn't open to you. A code-signing certificate issued to you as an individual by a certificate authority is. The SignPath Foundation signs open-source projects free, under strict conditions and under its own name. Options

Installing

An installer that sets up the service, its recovery actions, the Penna group and the app, and adds the installing user to the group. winget takes a silent installer and doesn't require a signature. PawnIO, if call 2 brings it in, installs on its own (winget install namazso.PawnIO) and may want a reboot.

Testing

The simulator carries over for everything in penna-core. win-ci holds the RTX 2060 SUPER through passthrough, so the M4 exit-path test can run on a real GeForce under Windows there, and win-ci can be the Windows CI runner. Nothing here has an AMD GPU or a laptop, and a VM never sees the board's Super I/O chip. Those start Documented, as M9 did.

An order to build it in

  1. W0The workspace builds on Windows, CI runs on win-ci, and penna watch reads NVML directly.
  2. W1The service, the pipe and NVML control, with every exit path tested on the 2060: Windows's M4.
  3. W2The Qt Quick app: tray glyph, popup, studio, setup.
  4. W3ADLX, the power mode and the vendors' WMI, Documented and simulated as in M9. Then the installer and signing: a first Windows release.
  5. W4Motherboard fans through PawnIO, if call 2 says so, starting with ITE and Nuvoton.
G · Decisions

Six calls before any code

Nothing is built yet. Parked on 23 October 2026: the Linux version is finished first. What you choose here will go into DESIGN.md as §11.4, with a Windows section beside §3 and §7.

  1. Windows starts with GPU fans and the power mode: NVIDIA through NVML, AMD through ADLX, laptops through Windows' power mode and, by vendor, their WMI. Motherboard fans stay with the BIOS for now. Recommended: all of it goes through the vendors' own drivers, so §11.2's first call holds unchanged, and NVIDIA can be tested on the 2060 in win-ci.
  2. Motherboard fans come later through PawnIO and Penna's own chip code, or not at all. Not through a LibreHardwareMonitor sidecar. Recommended: only Penna's own code can write each register's original to held.json before changing it, which is what hands fans back after a crash. This changes §11.2's first call for Windows: a signed driver that reaches only the fan chip's own ports, and never one on Microsoft's blocklist. The doctor would name the same ACPI risk it names for it87. The chip code would be ported from LibreHardwareMonitor's as its own MPL-2.0 crate, which keeps the rest MIT. Porting Linux's drivers instead would make the Windows build GPL-2.0.
  3. One workspace. Windows backends and the service sit beside Linux's in the same crates, behind cfg(windows). Recommended: one loop, one protocol, one set of tests, and a fix lands on both.
  4. The app is Qt Quick, reusing the plugin's components and Model.js, with the glyph in the tray. Recommended: the most reuse and the same look, and the same app for Linux desktops outside Omarchy. Tauri is the alternative if a smaller download matters more than reuse.
  5. Trust: members of a local Penna group may change fans; anyone signed in may watch. The installer adds the user who installs it. Recommended: the same rule as Linux's penna group (§7.4).
  6. Signing in your own name, with a certificate issued to you as an individual. Until then, beta builds go out unsigned, with SmartScreen's warning. Recommended: Penna is your project, and Microsoft's Artifact Signing doesn't sign for individuals in Portugal. SignPath is the free alternative, under its own name.
